切替が行われたという連絡を受けました。まず「コンテナが動いているか」「どちらが現用系か」「業務が成功しているか」を分けて確認します。

**学習目標：AP切替の成功だけでは、業務の正常性を判断できないことを理解する。**

## 1. コンテナの状態を見る

```bash
cd /root/lab
docker ps -a
```{{exec}}

`NAMES`列で3台を探し、`STATUS`列を確認してください。

| 表示 | 意味 |
|---|---|
| `Up` | コンテナが稼働中。業務成功を保証する表示ではない |
| `Paused` | コンテナ内の処理が一時停止している |
| `Exited` | コンテナが終了している |

## 2. AP2の役割と業務を別々に調べる

まず、役割に関するログを探します。昇格の記録は過去の行にあるため、末尾の数行だけに絞りません。

```bash
docker logs ap-server-2 2>&1 | grep -E 'starting as STANDBY|PROMOTED to ACTIVE'
```{{exec}}

`STANDBY`は待機系、`ACTIVE`は現用系です。`PROMOTED to ACTIVE`は現用系へ昇格した記録です。

続けて、最近の業務ログを読みます。

```bash
docker logs --tail 30 ap-server-2
```{{exec}}

`job SUCCESS`は業務成功、`DB connection failed`はDB接続の失敗を示します。エラーがあれば、その後ろの説明も読んでください。

## 出力から考えること

- AP2の昇格を示す行と、業務の成否を示す行は、同じ意味でしょうか。
- コンテナが `Up` でも業務が失敗するなら、次にどこを調べますか。仮説を1つ挙げてください。

<details>
<summary>ヒント1：確認する情報を分ける</summary>

コンテナの稼働状態はDocker、APの役割と業務結果はAPログで確認します。一つの表示だけで「復旧した」と判断しないでください。

</details>

<details>
<summary>ヒント2：エラーが指す接続先に注目する</summary>

昇格の記録があっても、直近のログに接続失敗が続いていれば、切替先で業務を継続できていません。エラーに出てくる接続先を、次のStepで調べましょう。

</details>

## CHECK前の確認

- AP1、AP2、DBそれぞれのコンテナ状態を確認した。
- AP2の昇格記録と、直近の業務結果を区別して説明できる。

このStepのCHECKは、AP1がpause状態、AP2とDBが稼働中であることを判定します。ログからの読み取りは、自分でも確認してから進んでください。
