# AP信頼性試験: DB接続枯渇の調査・暫定復旧・恒久対策

あなたは、とある業務システムの信頼性試験(冗長切替試験)を担当しています。

## システム構成

```````````````````````````````text
Dockerホスト
├── ap-server-1 : 現用系AP(Python、最大12並行の業務処理)
├── ap-server-2 : 待機系AP(現用系の異常時に自動昇格)
└── db-server   : PostgreSQL(業務DB: appdb)
```````````````````````````````

APは業務処理ごとにDBへ接続し、処理完了後に切断する方式です。

## 発生している事象

先ほど、現用系 `ap-server-1` に異常が発生しました。
設計どおり `ap-server-2` への自動切替は行われたはずですが、
**切替後も業務が回復していない**との連絡が入っています。

あなたのミッションは次の4つです。

1. AP切替が成功しているかを確認する(Step 1)
2. 業務が回復しない原因を調査する(Step 2)
3. 暫定復旧を行う(Step 3)
4. 恒久対策を適用し、再試験で効果を確認する(Step 4)

## 注意事項
